# Изолированный почтовый транспорт (выключен по умолчанию)

Реализованы SMTP SSL/TLS `smtp.mail.ru:465` и IMAP SSL/TLS
`imap.mail.ru:993`. Mail требует отдельный **пароль внешнего приложения**:
[официальная инструкция](https://help.mail.ru/mail/login/mailer/).
Обычный пароль ящика не подходит. Для чтения и отправки нужен доступ к Почте.

На 26.10.2026 пароль приложения не предоставлен, SMTP/IMAP и рассылка выключены.
Рабочий исследователь уже подключён к CRM через отдельный `iva_vpn` helper, но
тот допускает только leads/drafts POST. Его проверка не подтверждает почтовые
claim/ACK/inbox маршруты или доступ Mail.ru: сеть и credentials mailer требуют
отдельного подключения и приёмки.

Переменные конфигурации:

- `LEAD_MAIL_SENDER=ai.studio.ufa@mail.ru`
- `LEAD_MAIL_PASSWORD_FILE=/private/path/mail-app-password`
- `LEAD_MAIL_STATE=data/mail-state.sqlite3`
- `LEAD_MAIL_ENABLED=0` — никакого входа в почту по умолчанию.
- `LEAD_MAIL_SEND_ENABLED=0` — дополнительный независимый запрет отправки.

Файл пароля на Linux должен иметь права `0600`, принадлежать пользователю
службы и не быть ссылкой. Пароль не передаётся в аргументах процесса и не
попадает в диагностические результаты. На Windows права ограничиваются ACL
оператором. Состояние IMAP хранит идентификаторы, хеши и устойчивую дату первого
наблюдения, не тела писем. Оба файла SQLite должны принадлежать пользователю
службы; Linux устанавливает `0600`, systemd должен запускать с `UMask=0077`.

## Связка с очередью CRM

Скопировать `mailer/config.example.json` в `/etc/lead-flow/mail.json`.
По умолчанию оба переключателя выключены. Конфигурация содержит пути и лимиты,
**не пароль и не токен**. `LEAD_CRM_AGENT_TOKEN` или `crm_token_file` должен
содержать отдельный агентный токен не короче32символов, совпадающий с backend.
Токен из файла тоже требует `0600` и владельца службы. Только HTTPS origin;
HTTP, логин/пароль в URL, пути, query и автоматические редиректы запрещены.

```console
python -m mailer --config /etc/lead-flow/mail.json doctor
python -m mailer --config /etc/lead-flow/mail.json status
python -m mailer --config /etc/lead-flow/mail.json run
```

- `doctor` проверяет локальную конфигурацию и доступность файлов секретов.
  Он не делает сетевых вызовов и не подтверждает вход, новый API CRM или доставку.
- `status` читает локальную статистику последнего прохода и состояний попыток.
  Наличие файлов не создаёт, секреты/получателей/тексты писем не выводит.
- `run` при `enabled=false` не читает секреты, не открывает SQLite и не обращается
  к CRM/почте. При `enabled=true,send_enabled=false` читает входящие и передаёт
  ответы в CRM, восстанавливает подтверждения старых попыток, не берёт новые
  письма на отправку.
- При обоих переключателях выполняется один ограниченный проход: восстановление
  CRM-ack → проверка входящих → максимум3 новых атомарных claim → SMTP → CRM-ack.
  Дневной лимит, допуск кампании и suppression дополнительно применяет CRM.
  Сам mailer не утверждает черновики и не включает `CRM_OUTREACH_ENABLED`.

По умолчанию состояние хранится в отдельных файлах:

```text
/opt/iva/data/lead-flow/mail-dispatch.sqlite3
/opt/iva/data/lead-flow/mail-inbox.sqlite3
```

Эти файлы надо сохранять вместе в серверной резервной копии. Не удалять их для
«повторного запуска». Журнал привязан к CRM origin, ящику, INBOX и пути курсора;
изменение этих параметров требует контролируемого переноса состояния.
Записи попыток и входящей дедупликации сохраняются; короткая история проходов
ограничена100записями. Чужую финансовую базу или состояние личной почты Ивы
этот модуль не использует.

Переключатели из environment (`LEAD_MAIL_ENABLED`, `LEAD_MAIL_SEND_ENABLED`,
строго0/1) имеют приоритет над JSON. Пути можно переопределить
`LEAD_MAIL_PASSWORD_FILE`, `LEAD_MAIL_STATE`, `LEAD_MAIL_DISPATCH_STATE`,
`LEAD_CRM_AGENT_TOKEN_FILE`; origin — `LEAD_CRM_URL`.

`max_seconds=120` проверяется между безопасными действиями; начатая SMTP-транзакция
и запись её подтверждения не обрываются ради таймера. Каждый сетевой вызов имеет
собственный timeout. Большая входящая очередь дочитывается следующими проходами;
пока есть остаток или ошибка, новые отправки запрещены. Запуск сериализован
собственным локальным file lock и не меняет исследовательский/browser lease Ивы.

## Интерфейс для фонового работника

`send_one(draft, config)` принимает карточку отправки CRM с `from`, `to`,
`subject`, `body`, постоянным `message_id`. Результат `SendResult`:

- `accepted` — получено SMTP 250 после DATA; это подтверждение принятия
  сервером, **не доказательство доставки во входящие**.
- `failed_before_send` — сбой до передачи текста.
- `rejected` — явный отказ сервера 4xx/5xx после передачи DATA.
- `uncertain` — передача началась, окончательное подтверждение неизвестно.

Повторов нет. Сбой QUIT после 250 не меняет принятую отправку. Worker должен
получать атомарный claim в CRM, сохранять результат и не повторять uncertain.
Дневной лимит, запреты контактов и допуск письма применяет CRM **до** вызова
транспорта. Transport самостоятельно не выбирает получателей.

`runner.py` уже выполняет этот контракт. До SMTP коммитится `started`, после
результата транспорта — `pending_ack`. При потере ответа CRM следующий проход
повторяет **только** тот же идемпотентный результат. `started` после аварии
становится `uncertain`, даже если процесс мог не успеть открыть сеть. Повторная
выдача того же outreach ID/Message-ID не вызывает ещё одну SMTP-отправку.
После409отCRM попытка получает `reconciliation_required`; нужна сверка журнала
с CRM. Автоматического сброса, повтора письма или изменения итогового статуса нет.
Другие сбои транспорта останавливают текущий проход, сохраняя точный результат.

CRM должен иметь актуальные маршруты `/api/agent/outreach/claim`,
`/api/agent/outreach/{id}/result`, `/api/agent/replies`, `/api/agent/heartbeat`.
Старая версия Vercel без этих маршрутов не подключается автоматически.

`poll_replies(config, on_reply)` открывает INBOX только для чтения,
использует UID, UIDVALIDITY и BODY.PEEK. Первый проход запоминает границу
существующих писем. **Выполнить этот проход до первой отправки**. При смене
UIDVALIDITY письма перечитываются с сохранённой дедупликацией. Callback должен
подтвердить долговременную идемпотентную запись в CRM; исключение оставляет UID
для следующего прохода. В CRM уникальность обеспечивается Message-ID; локально
дополнительно хранится SHA-256 сообщения. После сбоя между записью CRM и
локальным checkpoint callback может повториться, поэтому его идемпотентность
обязательна. Для отсутствующей/некорректной/будущей даты используется сохранённая
дата первого наблюдения, поэтому повтор не меняет payload и не конфликтует вCRM.
Если курсор потерян после первой отправки, работник останавливается вместо
незаметного пропуска всех писем новым baseline.

В API reply передаются `message_id`, `from_email`, `in_reply_to`, `references`,
`subject`, `body`, `received_at`, `classification`, `classification_quote`.
Обычные ответы получают `needs_review`, а не автоматический интерес/отказ по
ключевым словам. Стандартные Auto-Submitted и delivery-status выделяются как
`auto_reply`/`bounce`. Идентификация реального клиента, проверка отправителя и
финальный переход этапа остаются в CRM. HTML-only письмо передаётся без
интерпретации HTML; оно остаётся на проверке. Письмо свыше лимита 1 МБ блокирует
курсор с `imap_message_too_large`, чтобы важный ответ не пропал незаметно.

Транспорт и связка проверяются имитаторами SMTP/IMAP/CRM, а формы данных —
настоящими схемами `Reply`/`TransportResult` API:
`python -m unittest discover -s tests -p 'test_mailer*.py'`.
Проверены потеря подтверждения, перезапуск после сохранения attempt, запрет
дубликатов, конфликт с истёкшим claim, входящий backlog/потеря курсора, лимиты,
защита HTTPS/redirect, стабильная дедупликация без Date и несовпадение отправителя.
Живой вход/отправка не выполнены; пароль не предоставлен. CLI готов; расписание
почты этим модулем не устанавливается. Семантическая классификация обычных ответов
пока не подключена: они сохраняются для проверки и препятствуют автоматическому
архивированию за отсутствие ответа. Сам mailer не обещает автоматический переход
такого письма в «Есть интерес» или «Отказ».
