# Lead Flow — отдельная мини-CRM

Автономный канбан для ведения лидов. Он не связан с основным сайтом проекта и использует собственную SQLite-базу `leads.db`.

В Vercel приложение автоматически использует Neon PostgreSQL из переменной `DATABASE_URL` или `POSTGRES_URL`. Локально без этих переменных используется SQLite.

## Запуск

Из корня репозитория:

```powershell
python -m uvicorn app:app --host 127.0.0.1 --port 8090 --reload
```

После запуска открыть <http://127.0.0.1:8090>.

Либо запустить файл `start.ps1` из PowerShell.

Новая база по умолчанию пуста. Автоматическое добавление старых демонстрационных
контактов отключено; существующие рабочие карточки сохраняются.

## Развёртывание на Vercel

1. Импортировать GitHub-репозиторий в Vercel.
2. Подключить Neon к проекту через Storage.
3. Добавить переменную окружения `CRM_PASSWORD` с паролем для входа.
4. Добавить `CRM_SECRET_KEY` со случайной длинной строкой.
5. Выполнить redeploy после проверки миграции на копии PostgreSQL. Новые таблицы создаются без замены существующих лидов.

На Vercel приложение не разрешает доступ к лидам без настроенного пароля.

## Возможности

- девять стадий: Новый, Предложение отправлено, Есть интерес, Ожидаем ответ, Диагностика, КП, Переговоры, Успех, Отказ;
- дата отправки и отдельный журнал принятия письма почтовым сервером; это не подтверждение доставки;
- перемещение карточек мышью между стадиями;
- карточка компании с контактами, вакансией, персональным предложением, заметками, бюджетом и следующим действием;
- дашборд за день, неделю, месяц и всё время: новые лиды, отправленные предложения, интерес, дожим, успехи и конверсия;
- журнал создания лидов и переходов между стадиями для накопительной аналитики;
- поиск по компаниям и содержимому карточек;
- счётчики активных лидов, лидов в работе и суммы воронки;
- REST API для будущей автоматизации: `GET/POST /api/leads`, `PATCH/DELETE /api/leads/{id}`.

## Исследование OCR и подготовка автоматизации — 26.10.2026

Приоритет владельца: сначала доказать потребность и предложение, затем подключать
рассылку. Материалы `research/` отделяют заявления конкурентов, пользовательские
отзывы и проверенные возможности собственного OCR. Наличие ПАУ у клиента не
означает, что его проблема решена. Универсальное JSON API не считается равноценной
заменой специализированной обработки судебных условий и сумм без испытаний.

- Карточки агента: потребность, сценарий, источники и цитаты, отдельно fit/intent.
- `/api/agent/*` требует отдельный `CRM_AGENT_TOKEN` минимум 32 символа.
- Очередь черновиков, атомарное резервирование, неизменный Message-ID и состояние
  неопределённой отправки без автоматического повтора.
- Ответы связываются с перепиской; отказы архивируются с запретом повторного контакта.
- DELETE теперь архивирует карточку. Архив без ответа включается отдельно;
  умолчание срока после включения — 14 дней.
- `worker/` — отдельный сохраняемый OSINT-процесс, preview по умолчанию.
  См. `worker/README.md`. Почтовый адаптер и его границы — `mailer/README.md`.
